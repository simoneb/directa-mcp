directa-mcp

Directa SIM's Darwin API (dAPI) as MCP tools — positions, balance, orders, candles and ticks.

Latest release … ·

Darwin listens on 127.0.0.1 only while it is running and logged in, so this is a local server: your client starts it on the same machine, and nothing is sent to Directa over the internet. There are no API keys — the authentication is Darwin being logged in.

You need Darwin (with API access enabled under Sviluppatori > Dev kit) and uv. Candles and ticks additionally need Directa's real-time data entitlement.

ChatGPT on the web and desktop accepts only remote HTTP servers, so it cannot run this one; Codex CLI is the way in there.

Orders are off until you turn them on. While DIRECTA_ENABLE_ORDERS is false, the tools that place, modify or cancel orders send nothing at all to Darwin. There is no simulated mode — the dAPI has no command that accepts an order without sending it to market, so with the flag on, orders are real, with real money.

What it exposes

check_connection, get_darwin_statusWhether Darwin is up, and whether the datafeed is enabled
get_positions, get_position, get_portfolio_overviewPositions, with derived prices and a reconciliation check against Darwin's own figures
get_account_balance, get_availabilityLiquidity, open P&L, equity, buying power
get_orders, preview_limit_orderThe day's orders; what an order would cost without placing it
place_limit_order, modify_order, cancel_order, cancel_all_ordersReal orders — gated
get_daily_candles, get_intraday_candles, get_candle_data_range, get_tick_dataOHLC candles and ticks — need the datafeed entitlement
start_darwinLaunches dGO so you can log in; the OTP stays yours

Every tool carries the protocol's annotations, so a client can group them by permission and ask for approval only where it matters.
